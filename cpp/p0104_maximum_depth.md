# 104. Maximum Depth of Binary Tree · C++17

[原题](https://leetcode.com/problems/maximum-depth-of-binary-tree/)的深度按根到最深叶路径上的节点数量计数。`int Solution::maxDepth(TreeNode* root)`借用judge提供的TreeNode，不修改边、值或所有权；输入必须是无环、不共享节点的有效二叉树，空树返回0。

显式DFS栈保存`(节点, 从根起的深度)`。根深度为1，每次弹出条目，把深度纳入best，然后对子节点压入depth+1。条目的深度正确性可由父子关系归纳；每个节点唯一可达且恰好被弹出一次，结束时best就是所有节点深度的最大值。任一非叶节点都存在更深的后代，因此这也等于最深叶节点的深度。

栈中的条目按值复制后再pop，避免持有已删除元素的引用。只将非空子节点入栈，所以弹出后能安全读节点。题目至多10000节点，最大深度10000，int足以保存深度。实现不使用递归，10000节点斜链不消耗同样深度的调用栈。

时间O(n)。二叉DFS栈中只需保留当前下降路径上尚未访问的兄弟分支，工作空间O(h)，最坏O(n)；斜链时此实现的待处理条目实际上至多1个。树由调用者拥有，算法不分配或释放TreeNode。

测试用独立BFS逐层计数为oracle，和生产DFS策略不同。枚举0..6节点的197个形状，另测各10000节点的左右斜链，核对返回值以及每条原left/right边和节点值不变。测试构造长链不递归；unique_ptr独立持有节点，不沿child指针递归析构。测试oracle的空间不计入求解算法复杂度。

A补写深浅分支的DFS账本：R.left=L（叶），R.right=M，M.left=N（叶）、M.right=O（叶）。栈左端为底、右端为顶；实现先压左再压右，所以先处理右分支：

| 弹出条目 | best更新后 | 压入孩子后的待处理栈 |
| --- | --- | --- |
| (R,1) | 1 | [(L,2),(M,2)] |
| (M,2) | 2 | [(L,2),(N,3),(O,3)] |
| (O,3) | 3 | [(L,2),(N,3)] |
| (N,3) | 3 | [(L,2)] |
| (L,2) | 3 | [] |

最后处理浅叶L时，best仍为3，不能赋成当前深度2。深度按节点计数，空树0、单根1。交换所有left/right不改变根到各节点的边数，最大深度不变；增加一个新根并以旧根为其唯一孩子，使所有原路径多一个节点，旧树非空时深度加1，旧树为空时新树为单根，同样从0变1。

A增加199次镜像核验并恢复原边，另对197个小树（含空树）加局部新根核验。两条10000节点斜链不再加根，以免超过原题节点上限；局部新根的生命周期覆盖调用，不交出所有权，每次都核对新根和旧树未被求解器改动。

空间上，单链每次至多压一个孩子，待处理条目最多1；高度h的满二叉树沿深度优先路径积累待访问兄弟，峰值O(h)，并非BFS的最大层宽数量。O(h)是上界，不声称每种高度h的树都用满h个条目。这些性质测试不冒充内存或递归栈实测。
