# 242. Valid Anagram · C++17

[原题](https://leetcode.com/problems/valid-anagram/)的基础合同是两个仅含小写英文字母的字符串，判断每个字母的出现次数是否完全相同。`bool Solution::isAnagram(const std::string& s, const std::string& t)`用const引用借用两串，不复制或修改输入；可由judge直接调用。原题每串长度1..50000，空串与空串返回true是扩展。本实现不扩展为Unicode码点、大小写折叠或任意字节计数。

先排除长度不同。26个有符号计数槽初始为0；每处理一对同下标字符，对s的字母加1，对t的字母减1。处理前i项后，每个槽恰为该字母在两个前缀中的次数差。结束后所有槽为0等价于每种字母的完整次数相等，即一个字符串可以通过重排得到另一个。中途的负值正常，例如s='ab'、t='ba'的第一轮，不能提前据此判错。

合同中的'a'..'z'保证槽下标0..25合法。计数绝对值不超过50000，int足够；不能只比较出现过哪些字母，例如'aacc'与'ccac'集合相同但次数不同。常数字母表下时间O(n)，额外空间O(26)=O(1)，const引用避免参数复制额外占用O(n)空间。

独立测试分别排序两个字符串再比较，交叉枚举abc上长度0..5的364个字符串，共132496对；另有3个明确例子和4个边界，覆盖50000个相同字母、仅一个字符次数变化、长度相差1和全部26个字母逆序。排序只用于测试oracle，生产实现不排序。

A补写s="ab"、t="ba"的有符号差账本，只列a、b两个槽，其他槽始终为0：

| 已处理字符对 | a槽 | b槽 | 此时能否判错 |
| --- | --- | --- | --- |
| 尚未处理 | 0 | 0 | 不能，前缀为空 |
| 第0对a/b | +1 | −1 | 不能，后缀可能抵消 |
| 第1对b/a | 0 | 0 | 已处理全部字符，返回true |

循环不变量描述的是两个已处理前缀的次数差，中途非零或负数都不是整串不匹配证据。反例s="aacc"、t="ccac"两串都出现a、c，长度也相同，但最终a槽+1、c槽−1，必须返回false；集合或长度均不足以替代次数。

交换s、t使每个最终差槽取负，所有槽是否全零保持，因此判定对称。在两串末尾添加同一个合法小写字母，等于同一个槽各加1和减1，最终差不变；长度相等与否也保持。A对132496个小字符串对各增加一次交换和一次同添'z'检查；原长度0..5，添加后1..6，没有把50000长度边界再加1。新增期望仍来自原独立排序oracle，不复用计数实现。空串情况按既有扩展处理，不借此扩展Unicode合同。
